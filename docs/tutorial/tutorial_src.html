Get started

Build a client deck with Slide Lab, step by step

Accurate as of , Slide Lab version (the code's short ID). The newest copy is always in your Slide Lab folder: see Updates and help.

Slide Lab is a set of add-ons for Claude (the AI assistant you chat with in the Claude desktop app) that builds a client-branded PowerPoint deck with you. You bring the message, the audience, your notes and the client's PowerPoint template; Claude helps shape the story, designs every slide on that template, lets you pick the designs, checks the result and hands you a normal, editable .pptx file.

New to Slide Lab? Check Before you start, then follow steps 1 to 8. In the middle of a deck? Jump to your step in the contents menu.

The running exampleThroughout this guide we follow one real Slide Lab build: a 10-slide deck called "Meridian: Southeast Asia entry". Meridian is a made-up company; its template and every number are invented. The timings in this guide were measured on that build. Its files are built into this guide, so they open even if this page was emailed on its own: the storyline, the review page (the real first-round page, options per slide) and the finished deck.

Before you start

  • Slide Lab is installed
    Not installed yet? Install Slide Lab

    Follow the install guide (a Word file; click to download it). In short: get Claude, Python and LibreOffice from your company's software portal (on Windows, PowerPoint can stand in if LibreOffice is not approved); then paste one setup request into Claude and click Allow each time it asks; it ends by showing a table where every row should say OK; restart Claude. Setup allows Slide Lab's own steps to run without asking each time; it does not allow anything else. The setup request:

    Install Slide Lab for me: clone https://github.com/mperaltajr/skills into my .claude\skills folder (~/.claude/skills on a Mac), or git pull if it is already there. Then follow the "Doing it by hand" steps in its README.md, one command at a time so I can approve each, and finish by running doctor.py and showing me its table.

    Time: .

  • A work folder on your own drive Setup creates C:\Users\<you>\Slide Lab\sessions\ with a Desktop shortcut. Each client gets a folder inside it (...\sessions\<Client>\), and each deck a dated session folder inside that. Templates can stay anywhere.
    ImportantKeep the session folder out of OneDrive and Dropbox: there, builds are noticeably slower and previews can time out. Copy the finished deck to OneDrive or SharePoint afterward.
  • The client's PowerPoint templateA widescreen .pptx. Once per template, Claude reads it and you tell it which colors and layouts to use ("registering" the template); after that it is on your pick-list and every deck on it matches automatically. You do this in step 2: .
  • Your message, audience and notesLittle material is fine: Claude starts from the basics (what decision you want, from whom).

Your first deck

Filled circles are your turn; hollow circles are Claude working, so you can do other work. Phrases with a Copy button can be pasted straight into Claude.

  1. 1

    Start Slide Lab

    Your turn In the chat

    1. Open the Claude desktop app, go to the Code tab and type /slide-lab or just ask for a deck. Once a day Claude first checks for an update; if there is one, it says in a sentence or two what changed and asks:

      Claude asks"A Slide Lab update is available. OK to install it now? It takes under a minute."

      Answer yes or no. If it then says to restart, close and reopen Claude before building. Say no if you are mid-deck: it goes on with your current version and does not ask again that day; it asks again tomorrow.
      You'll seeThe question in the chat. With no update, Claude says nothing and goes straight on.
    2. Pick a number from the menu, or describe the deck. If your request is specific, Claude names the route in one line and starts. If not, it shows a menu of 5 choices and waits; it does not guess.
      You'll seeThe menu, in the chat:
      1. Make a new deck: from a topic, your notes, a storyline you already have, or an RFP (a proposal scored against the client's criteria). Claude asks one question to tell these apart. It always builds a new file
      2. Change a deck: one Slide Lab built, or any other PowerPoint file (see Change a deck later)
      3. Check a deck: quality-check a finished .pptx before you send it
      4. Set up a client's template: one-time setup of a template's colors and layouts before building (step 2)
      5. Not sure: Claude asks a couple of questions and points you the right way
    If something goes wrong
    Claude picked the wrong route
    Say so, and it shows the menu.
  2. 2

    Set up the client's template

    Your turn Once per template

    A template is the client's PowerPoint file with their colors, fonts and slide layouts. Registering it means telling Slide Lab which color does which job and which layouts to use. Claude works on its own copy; your original file is never changed. All of this happens in the chat.

    Already set up? Go to step 3.

    1. Type Register my template at C:\path\to\client-template.pptx. Claude checks the slide size: it must be widescreen (16:9) at 13.333 x 7.5 inches, PowerPoint's standard widescreen size.
      You'll seeA message in the chat about the slide size.
    2. Answer three color questions, one at a time: the main brand color, the highlight color and the cover background. In the same pass Claude asks whether you have a real deck that uses this template. Give its path, or say no. With a deck, Claude picks 3 or 4 of its best content pages so the designs match the client's look.
      You'll seeA list of every color Claude found, each with a plain name, its color code and where it appears ("dark navy, 0B3C49, title bars on content slides"). Claude never pre-picks an answer: the automatic guess was wrong on every template tried so far.
    3. Pick the default content layout (used for most slides) and the cover layout from the pictures Claude shows. Optional: name one slide in the template that shows how every content slide should look.
      You'll seeA picture of each layout in the chat. Claude will not finish without the default content layout, because later builds need it.
    4. Claude builds one sample slide on the template and gives you its path. Open it in PowerPoint. Check the title, takeaway, footnote and source sit where they should and fit, and that the main and highlight colors are not swapped. Tell Claude "it looks right".
      You'll seeClaude marks the template confirmed and adds it to your pick-list.
    TipUnsure which color is which? Open a real deck from the client: the main color carries titles and bars, the highlight is used sparingly for emphasis.

    Meridian exampleMeridian's template was registered with dark navy (0B3C49) as the main color, amber (F2A541) as the highlight color, a navy cover background, "Title and Content" as the content layout and "Cover" as the cover layout.

    If something goes wrong
    The template is another 16:9 size
    Claude offers a one-command fix and registers the fixed copy.
    The template is 4:3 (the older, squarer size)
    It is refused: ask the client for a widescreen version.
    The sample slide looks wrong
    Say what is wrong; Claude corrects the setup and makes a new sample.
    A build refuses the template
    Builds refuse a template you have not confirmed. Finish this step first.
  3. 3

    Shape the storyline with Claude

    Your turn A conversation in the chat

    Before any slide exists, Claude coaches the argument. The result is a dot-dash storyline: one bold claim per slide (the dot) with its supporting points (the dashes). Read the dots top to bottom and they should tell the whole story.

    Claude writes each headline as a fact the audience can check, with a number where there is one ("Only Vietnam and Indonesia clear both the size and the readiness bar"), not a slogan ("Vietnam is the clear winner"). Claude also saves a brief, the detailed plan the slide designs are built from.

    1. Describe the deck: number of slides, main message, audience, and paste your notes or numbers. For example: Build me a 10-slide deck. Main message: ... Audience: ... Here are my notes: ...
      You'll seeClaude says back what it saw in your material and asks 1 to 3 pointed questions.
    2. Answer, push back, reword. If a slide's claim is not what you mean, say so in your words; it rewrites.
      You'll seeClaude proposes one structure for the deck with its reasons, then goes slide by slide: the claim first, then the support.
    3. Read the summary message Claude sends, then reply once: type Build to accept the rewrites and build the slides, "save only" to stop with the storyline, or say what to change. To keep a flagged line as it is, say why in your own words; "skip" alone is not accepted. Until you answer, nothing is saved or built.
      You'll seeThe summary message, in three parts:
      1. The setup: the session folder (it suggests C:\Users\<you>\Slide Lab\sessions\<Client>\), the client and topic, the template and the default content layout.
      2. A table of any problems in the storyline, each with a suggested rewrite: a headline that is a slogan instead of a fact, a claim with no number behind it, or a headline that will not fit on one line in the template's own font.
      3. The question below.

      Claude asks"Build, save only, or tell me what to change?"

      You'll seeAfter your answer, file paths in the chat: Claude saves the storyline (as a Word file, a text file and a web page), the brief and a list of open gaps in the session folder's _session folder. With "build", it goes straight on to step 4.
    Note"Save only" is a normal finish if you only needed the storyline: Stop here, I only need the storyline

    Meridian exampleThe storyline's main claim: "Meridian should enter Southeast Asia through Vietnam first, then Indonesia, starting with $12M of Phase 1 funding." See all 10 dots and their dashes in the example storyline. (That storyline was written from a finished data sheet, so it took minutes; a real one usually takes longer.)

    If something goes wrong
    You have little material
    That is fine; Claude starts from the basics (what decision you want, from whom).
    Your template is not in the list
    Claude stops and has you register it first (step 2).
    Your session folder is in OneDrive
    Claude warns once that builds will be slower. See What makes it slower.
  4. 4

    Wait while Claude designs the slides

    Claude works, you can do other work

    Claude designs every slide at the same time (up to at once), genuinely different design options per slide, not just color swaps. Then it draws a preview of every option, makes the review page and opens it in your browser.

    You'll seeProgress messages in the chat, then the review page's path (a file called REVIEW.html in the session folder). Full timings
    If something goes wrong
    It stops with an error
    Type /slidelab-log. It writes the bug report for you.
    Previews time out
    The session folder is probably in OneDrive. See What makes it slower.
  5. 5

    Pick a design for every slide

    Your turn On the review page, in your browser

    The review page opens in your browser (Edge or Chrome). It is a file on your own computer; nothing is uploaded. The designs on it are quick drafts: the real title, takeaway and page number are added in step 6.

    1. Look at the review page Claude opened. Closed it? Paste its path into your browser's address bar, or double-click REVIEW.html in the session folder.
      You'll seeOne card per slide, with its options side by side.
    2. For each slide, click PICK A, PICK B or PICK C. Click REPLACE THESE to get a new design for that slide, or LEAVE OUT to drop it from the deck.
      You'll seeA "PICKED" mark on the chosen option, and the counts at the top go up.
    3. Optional: click any of the quick-feedback buttons, such as Too sparse, add detail or Add process structure: numbers, icons (the page lists the rest), or type a note under More detail (optional). Notes travel with your choices, so a pick plus a quick-feedback button asks for a small change without a new design.
    4. Click Build my deck, then paste the message it copies into Claude, unchanged. It reads like Picks: 1B 2C 3A ... (check 1a2b3c4d).
      You'll see"Build command copied" on the page. Claude records exactly what you picked and moves on to step 6.
    TipYour choices save in this browser, so you can close the page and come back later in the same browser.

    Meridian exampleOpen the example review page to click around. The buttons work and copy a message, but there is no build behind it, so there is nothing to paste it into.

    You marked a slide REPLACE THESE: what happens next

    Build my deck copies a request for new designs instead. Paste it into Claude, and say what you want different in the notes or in the chat.

    Claude redesigns only the slides you marked, new design each by default, using your notes, and keeps every other pick. With one design there is nothing to pick, so it goes straight on to the final check page (step 6). Time: . Still not right? Say so on the final check page and it redesigns again.

    Want alternatives? Ask for them "with 3 options". Claude makes a new review page for those slides and opens it; decide on them and click Build my deck again, as in this step. You can repeat this round as often as you like.

    If something goes wrong
    Build my deck will not copy anything
    It refuses until every slide has a decision, and lists the slides still missing one.
    Claude refuses the picks
    The message was edited, cut short or copied from an older review page; its check code catches that. Click Build my deck again and paste the message unchanged. Do not retype it.
    Your choices are gone
    They save in the browser you used. Open the page again in that same browser.
  6. 6

    Check the finished slides

    Your turn On the final check page

    While you wait, Claude turns each picked design into real PowerPoint: text you can edit and shapes you can move, not pictures. Things that need drawing by hand (curved diagrams, rotated text, images) Claude draws itself. Then it puts every pick on your real template with its real title, takeaway and page number, makes the final check page (FINAL-CHECK.html) and opens it in your browser. Time: ; . Full timings

    1. Look at every slide for anything overlapping, cut off or crowded.
      You'll seeEvery finished slide, exactly as it will be built.
    2. Check the box at the top: it lists any number or label on a slide that is not in your brief.
    3. All good: click Build it and paste what it copies into Claude.
      You'll see"Build command copied" on the page. Claude builds the deck and runs the quality check (step 7).
    4. Something wrong: type it in the box that reads Something needs fixing? Say which slide and what. then click Send fixes and paste what it copies. Name the slide and say what is wrong ("slide 4: the right column is cut off"); the more specific, the better the fix.
      You'll seeClaude redesigns the affected slides and opens a new final check page in your browser.
    ImportantA number in that list that you did not expect needs a fix: the quality check cannot tell an invented number from a real one.
    If something goes wrong
    You are not sure about the look
    Build it: the quality check runs next and catches overflowing or cut-off text.
    You lost the copied text
    Click the button again.
    Claude reports a problem on a slide
    It says which one and what it suggests.
    The cover has no page number
    Covers are never numbered; that is intended.
  7. 7

    Answer the quality check

    Claude works, then asks you

    Claude builds the deck: a .pptx in the session folder, named after the deck's topic. Build time: . Then the quality check opens a picture of every slide and reads it area by area, looking for text that overflows, type that is too small, things out of line and leftover placeholder text. Each finding gets a severity:

    • Critical: must be fixed
    • Major: fix it, or give your reason to keep it
    • Advisory: a suggestion, never blocks

    Claude does not call a deck done while a Critical or Major finding is open.

    1. Read the findings: one table in the chat, with Claude's offer to fix them. Disagree with a Major finding? Say why in your own words; Claude records your reason.
    2. Say Fix it (or "build it").
      You'll seeClaude redesigns each flagged slide (one design each), builds the deck straight away and checks the new deck again. There is no page to look at again: it does not send you back to either review page. Time: .
    3. Open the deck.
      You'll seeThe deck's path in the chat, once no Critical or Major finding is open.
    NoteClose, not pixel-perfect. Slide Lab gets every slide as close to finished as it can on the client's brand, but plan on a little hand polishing before you send: a line of wording here, a small nudge there. That is why you get real, editable PowerPoint and not a picture of a slide.

    Meridian exampleThe quality check flagged slide 5; after "fix it" Claude redesigned that slide, rebuilt the deck and checked it again. The result is the example deck.

    If something goes wrong
    The build fails
    Claude says why. If that is unclear, type /slidelab-log.
    A fix still looks wrong
    Say what you want; you can also ask to "rebuild slide N" for a fresh design (see Change a deck later).
  8. 8

    Say "The deck is good"

    Your turn

    1. When you are happy, type The deck is good. Claude only cleans up when you say so: until you say it, the build folder is kept in full (nothing is deleted without your say-so).
      You'll seeA short message in the chat. Claude frees about 90% of the build folder's space and says how much. It keeps the deck, the final check page, the storyline, the brief, your decisions and the picked designs (so you can still rebuild a slide later). The review page itself and the unpicked options are deleted.
    2. Copy the deck to OneDrive or SharePoint. This step is yours. Copy only the finished deck; keep the working folder on the local drive.
    3. Later, to free space: Clean up my finished decks
      You'll seeA table in the chat of your older decks, with how much space each would free and when each last changed; then Claude asks which are final. It takes a minute or two, and it never cleans a deck you did not name.

Common questions

Do I need to know how to code or design?

No. You talk to Claude in plain English and click buttons on two web pages. Claude asks before it runs anything on your computer; click Allow when it does.

Why did Claude stop and wait?

Slide Lab is built to stop at certain points and wait for your answer. A stop is not a bug: Claude is asking for something only you can decide. Nothing moves on until you answer.

If you do not answer: nothing is built, saved or deleted. Answer in the chat, or click the button on the page it opened.

What if I don't like any of the designs for a slide?

Click REPLACE THESE and say in the notes what you want different. You get new design by default; say "with 3 options" if you want alternatives. For a small change, pick the closest option and add a quick-feedback button or a note instead.

Can I get every option in one PowerPoint file?

Yes. All options in one deck on the review page builds every option, not just your picks, into one deck for side-by-side comparison. It costs several times more than a normal build, so the page warns you and asks before it copies anything. Use it rarely.

Why do I paste a message back into Claude?

The review pages are files on your computer and cannot talk to Claude directly. The copied message carries your exact choices with a check code, so nothing is retyped or misread. Paste it unchanged.

Can I keep my work in OneDrive?

Keep the session folder on your computer's own drive (C:\Users\<you>\Slide Lab\sessions\). In OneDrive, builds are noticeably slower and previews can time out. Copy the finished deck to OneDrive or SharePoint afterward. The template itself can live anywhere.

Can I edit the charts afterward?

Charts are drawn from shapes for a clean, on-brand look, so they are not linked to a datasheet. Either ask Claude to rebuild the slide with new numbers, or say "Export the chart data to Excel" and paste the sheet into think-cell or a normal PowerPoint chart.

Is my client's template safe?

Yes. Slide Lab works on its own copy and never changes your original file. Your work stays on your computer.

Can it work on a deck I already have?

Yes, "Change a deck" in the menu: fix text or numbers, redesign a slide and drop it back into your deck, or refresh a recurring deck with this cycle's text. It always writes a new file. See Change a deck later.

Does it work on a Mac?

Yes. The install guide covers Windows and Mac. Paths look different on a Mac (your home folder instead of C:\Users\<you>).

Updates and help

Updates
Once a day, at the start of a session, Slide Lab checks for an update and asks "A Slide Lab update is available. OK to install it now?" Say yes (it never updates in the middle of a build). If it says to restart, close and reopen Claude. To check any time, say Update Slide Lab. This guide updates too.
Install or setup problems
Say Check my Slide Lab setup. Claude runs a checker that prints a table of what is OK and, for anything that is not, what to do. It changes nothing on its own.
Something went wrong in a session
Type /slidelab-log. Claude writes the report for you; send the file privately to Mario Peralta on Teams or by email.
Ideas and other feedback
Tell Mario Peralta on Teams, or whoever shared Slide Lab with you. Do not post client names or slide content anywhere public. Say what you asked for and what you got.
Get the newest copy of this guide
Always in your Slide Lab folder, C:\Users\<you>\.claude\skills\Slide-Lab-Tutorial.html, updated when Slide Lab updates. A copy someone emailed you may be out of date.
