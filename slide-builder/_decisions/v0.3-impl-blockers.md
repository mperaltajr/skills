v0.3 implementation blocker notes (2026-05-28)
==============================================

These are minor interpretation calls the implementation chat made.
The fresh-context audit chat (cleanup-chat-cannot-self-declare) should
verify each is acceptable or flag for rework.

1. patches/patches.py has no TEXT_DARK hardcodes that ignore text_role.
   The plan called for patching '~3 helpers that hardcode TEXT_DARK'; grep
   found only parameter defaults (add_text(... color=TEXT_DARK) and
   add_table(... body_text=TEXT_DARK)) which callers override per-shape.
   Decision: no change. Pattern helpers in slide-builder/_decisions/gallery/*.py
   reference TEXT_DARK directly but those are exemplar option scripts, not
   live pipeline code (allowlisted in check_chrome_field_single_source).

2. The smoke build's 'bespoke cover' slot is substituted with a second
   body-canonical layout. OTC's Cover layout carries only body-type
   placeholders (no TITLE placeholder), so _extract_bespoke_boxes() leaves
   chrome.cover.title=None and any add_title_block(chrome=cover) raises
   ChromeSidecarMissingError. The bespoke cover path is still exercised by
   the synthetic 'cover_dark' fixture in tests/fixtures (which has a Title
   placeholder by python-pptx default). Decision: skip OTC Cover in the v0.3
   smoke build; verify the bespoke path via the synthetic fixture.

3. commit_method is written to a sibling marker file
   (<stem>.chrome.commit_method.txt) rather than embedded in chrome.yml.
   Reason: ChromeSpec is a pydantic model that rejects extras strictly.
   Adding 'commit_method' to the schema would require schema v3 and would
   surface to every layout reader. The sibling marker keeps the audit-trail
   field outside the validated schema. Acceptable interpretation; flag if
   the v0.2 design lock § D6 wants it inside chrome.yml literally.

4. The register.html cluster picker (section 3) renders 6 cards + a
   collapsed 'Show all slide designs' details. Card heuristic: group by
   placeholder_count + background. Per the plan: 'cluster duplicates by
   title-y ± 0.2" tolerance + body-box ± 0.3" tolerance'. The implementation
   uses placeholder_count + background as a proxy since title-y is only
   populated for bespoke layouts (body-canonical have title=null). This
   covers the FedEx-style case where layouts genuinely differ by placeholder
   count, but may over-cluster on templates where multiple body layouts have
   identical placeholder counts. Acceptable v0.3; revisit if a real template
   surfaces the over-cluster behavior.
