# Pattern B — Fidelity measurement spec

> How "≥90% visual fidelity" gets measured concretely. Defines SSIM thresholds, zone definitions, and baseline-capture procedure.

**Status:** locked 2026-06-16. Depends on Decision 5 (severities), SPEC.md zones, Spec 4 (translator self-check).

---

## 1. SSIM as the metric

**Structural Similarity Index Measure** (SSIM, Wang et al. 2004) is a perceptual image-comparison metric scoring 0.0 (no match) to 1.0 (identical). Available in Python via `scikit-image`:

```python
from skimage.metrics import structural_similarity as ssim
score = ssim(img1, img2, data_range=255, channel_axis=-1, win_size=7)
# score ∈ [-1.0, 1.0]; typical range for similar images is [0.6, 1.0]
```

**Why SSIM, not pixel diff:**
- Pixel diff is over-sensitive to anti-aliasing noise that humans don't perceive
- SSIM matches perceptual similarity (luminance + contrast + structure)
- Industry-standard metric for "do these two images look the same"

**Why not LPIPS / DreamSim / CLIP-similarity:**
- Heavier deps (need PyTorch + a model)
- Deterministic SSIM is enough for the use case (we're not comparing artistic intent; we're verifying a rendering matched)

`scikit-image` is added to `requirements.txt` for Pattern B. ~30 MB install.

## 2. Zones

The 1280×720 canvas is divided into four zones for measurement:

```
┌─────────────────────────────────────────────┐  y=0
│  TITLE ZONE                                 │  height: 60–100px (varies by template)
├─────────────────────────────────────────────┤  y=title_zone_bottom
│  SUBTITLE ZONE                              │  height: 30–60px (varies)
├─────────────────────────────────────────────┤  y=body_top_y_px
│                                             │
│  BODY ZONE                                  │  height: varies; biggest zone
│  (the one that really matters for Pattern B)│
│                                             │
├─────────────────────────────────────────────┤  y=body_bottom_y_px
│  FOOTER ZONE                                │  height: ~50px
└─────────────────────────────────────────────┘  y=720
```

Zone boundaries come from `chrome.yml::default_content_layout`:
- `title_zone`: y=0 to title_box.bottom (title_box.y + title_box.height)
- `subtitle_zone`: title_box.bottom to subtitle_box.bottom (if subtitle placeholder exists)
- `body_zone`: subtitle_box.bottom (or title_box.bottom if no subtitle) to body_bottom_y_px
- `footer_zone`: body_bottom_y_px to 720

For Pattern B, the **body zone is the load-bearing measurement**. Chrome zones are template-inherited (rendered by master); they should always match because they're not generated by the translator. Body zone SSIM tells us whether the translator faithfully reproduced what the HTML render showed.

## 3. Thresholds (per Decision 5)

```python
THRESHOLDS = {
    "critical": 0.70,   # below this: build fails (R4.7-class)
    "major": 0.85,      # below this: flag in REVIEW.html (Major)
    "pass": 0.90,       # at or above: clean
}
```

**Threshold rationale:**
- 0.90+: visually indistinguishable to a critic with experience. Ship.
- 0.85–0.90: minor differences (slight color drift, anti-aliasing artifacts, sub-pixel positioning). Surface as Major; user decides whether to ship or re-translate.
- 0.70–0.85: meaningful divergence (text position visibly different, color clearly off, missing or extra shape). Critical-adjacent; surface as Major with strong language. Investigate.
- <0.70: structural failure (wrong layout, missing major elements, wrong template). Critical hard-fail. Halt build.

These thresholds apply PER ZONE, not whole-slide. A slide with body=0.92 + title=0.88 + footer=0.71 has one zone below 0.85 (footer Major) but is mostly clean. A slide with body=0.65 is Critical regardless of other zones.

## 4. Where measurement happens

Three measurement points in the pipeline:

**(a) Translator self-check** (Spec 4 §8):
- After translator emits `option_X_native.py`, execute it → produce `option_X_native.pptx`
- Render that pptx to PNG via LibreOffice (existing `slide-qc::render_slides.py`)
- Compute per-zone SSIM against the picked `option_X.png` (HTML render target)
- Emit `LOW_CONFIDENCE` marker if any zone < Critical threshold

**(b) finalize_deck.py post-graft check:**
- After graft + theme, render the final themed PPTX to PNG
- Re-measure per-zone SSIM (in case grafting introduced drift)
- Surface in REVIEW.html alongside the option

**(c) Regression baseline:** before Pattern B ships, capture baselines for the OTC brief:
- Run the OTC brief through the CURRENT (pre-Pattern-B) pipeline
- Save the rendered PNGs as `tests/baselines/otc/slide_NN_baseline.png`
- After Pattern B ships, re-run the same brief; compute SSIM against baselines
- Any slide with SSIM < 0.85 against the baseline is flagged as a regression (Quality Guarantee #3)

## 5. The baseline-capture script

`tests/capture_baseline.py` (new):

```python
"""
Capture baseline PNGs for regression testing Pattern B.

Run on the CURRENT pipeline BEFORE Pattern B lands. Run again after
Pattern B ships to verify Quality Guarantee #3 (no silent regressions).
"""
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "scripts"))

import subprocess

BRIEFS = [
    {
        "name": "otc",
        "brief": Path(r"C:\...\OTC Final Deliverable\_session\narrative-brief-otc.md"),
        "template": Path(r"C:\...\FedEx_OTC_Template.pptx"),
    },
    # add more representative briefs over time
]

BASELINE_DIR = Path(__file__).resolve().parent / "baselines"

def capture(brief_name: str, brief_path: Path, template_path: Path) -> None:
    out = BASELINE_DIR / brief_name / "build"
    out.mkdir(parents=True, exist_ok=True)
    # run current pipeline
    subprocess.run(["py", "-3", "scripts/build_deck.py",
                    "--brief", str(brief_path),
                    "--template", str(template_path),
                    "--out", str(out)], check=True)
    # ... (dispatch workers, finalize)
    # copy each option_X.png to BASELINE_DIR/<brief_name>/slide_NN_X_baseline.png
    for slide_dir in sorted(out.glob("slide_*")):
        slide_n = int(slide_dir.name.split("_")[1])
        for letter in ("A", "B", "C"):
            png = slide_dir / f"option_{letter}.png"
            if png.exists():
                dst = BASELINE_DIR / brief_name / f"slide_{slide_n:02d}_{letter}_baseline.png"
                dst.write_bytes(png.read_bytes())

if __name__ == "__main__":
    for b in BRIEFS:
        capture(b["name"], b["brief"], b["template"])
    print(f"Baselines captured to {BASELINE_DIR}")
```

## 6. The regression check

`tests/regression_check.py` (new):

```python
"""
Compare Pattern B output against captured baselines.

Run after every Pattern B refactor commit. Fails CI if any slide
SSIM-drops below 0.85 against its baseline.
"""
from pathlib import Path
from skimage.metrics import structural_similarity as ssim
from skimage.io import imread

BASELINE_DIR = Path(__file__).resolve().parent / "baselines"

def measure_regression(brief_name: str, build_dir: Path) -> list[dict]:
    results = []
    for baseline in sorted((BASELINE_DIR / brief_name).glob("slide_*_baseline.png")):
        slide_n = int(baseline.stem.split("_")[1])
        letter = baseline.stem.split("_")[2]
        current = build_dir / f"slide_{slide_n:02d}" / f"option_{letter}.png"
        if not current.exists():
            results.append({"slide_n": slide_n, "option": letter,
                            "status": "missing-current"})
            continue
        b_img = imread(baseline)
        c_img = imread(current)
        if b_img.shape != c_img.shape:
            results.append({"slide_n": slide_n, "option": letter,
                            "status": "dimension-mismatch",
                            "baseline_shape": b_img.shape, "current_shape": c_img.shape})
            continue
        score = ssim(b_img, c_img, data_range=255, channel_axis=-1, win_size=7)
        results.append({"slide_n": slide_n, "option": letter,
                        "ssim": score,
                        "status": "regression" if score < 0.85 else "ok"})
    return results
```

Run this after every Pattern B build during the refactor. Any `regression` status halts the merge.

## 7. SSIM nuance: anti-aliasing and font rendering

SSIM is robust to minor anti-aliasing but sensitive to font-rendering differences. Two cases that produce false-positives:

1. **LibreOffice vs Chromium font rendering** differ subtly. The HTML PNG (Chromium-rendered) and the native PPTX PNG (LibreOffice-rendered) will have slightly different glyph hinting. SSIM penalizes this even when text is identical.
   - **Mitigation:** target threshold is 0.85, not 0.95, accounting for this expected noise.
   - **Future improvement:** render both pipelines via the same engine (LibreOffice headless can render HTML; or use Chromium for both).

2. **Sub-pixel positioning** from CSS `position: absolute` vs python-pptx EMU rounding produces 1-pixel shifts. SSIM with `win_size=7` (default) averages over 7×7 windows so 1-pixel shifts barely register.

If false-positives become a problem in practice, alternatives:
- Use `gaussian_weights=True` (slower but more perceptually accurate)
- Combine SSIM + edge-detection diff (catches structural differences without penalizing aa noise)
- Hand-curate threshold per zone (title/footer get 0.90, body gets 0.80)

For v0, stick with locked thresholds. Tune from real data.
