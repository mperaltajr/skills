## 1. The pain this solves

Mario builds decks against client templates (FedEx, NFL, internal Accenture). Current `slide-builder` builds every slide on a blank 1280×720 canvas at hardcoded `twins/helpers.py` positions, then grafts onto the client template's blank layout. Result: every built slide is "slightly off-spec" relative to the client's chrome (title position drift, footer-band collisions, lost gradient frames, lost cover backgrounds). Mario hand-edits every slide to translate.

This design eliminates the hand-editing for **90% of body slides** by inheriting master chrome correctly and keeping Slide Lab's canonical positions consistent across the deck. Cover-class layouts inherit positions from the template exactly.

## 2. The architecture decisions (locked)

### 2.1 Two layout classes — body-canonical vs bespoke

| Class | Definition | Position source | Chrome source |
|---|---|---|---|
| **body-canonical** | Blank-ish body + chrome frame; master decorates, layout is mostly empty (FedEx body layout, Accenture body layout, ~90% of consulting body layouts) | **Slide Lab's canonical helpers** (`twins/helpers.py`) | Master flows through via `finalize_deck.py` graft. Layout placeholders stripped via existing `_strip_layout_placeholders`. |
| **bespoke** | Art-directed (cover, section divider, dark hero) — chrome IS the slide, positions matter | **chrome.yml** extracts placeholder positions per layout | Master chrome inherited identically; placeholders at extracted positions |

Classification happens at template registration. Heuristic: layout has ≤2 art-direction shapes outside chrome zones → `body-canonical`; everything else → `bespoke`. **User confirms classification in `register.html` before commit** — never silent.

### 2.2 Don't modify the source `.pptx`

Mario asked whether the template's placeholders could be repositioned to match Slide Lab's canonical positions. **Decision: don't modify the source `.pptx`.** Mario's instinct (keep positions consistent across the deck) is achieved without touching the template by:

- For `body-canonical` layouts: Slide Lab uses canonical positions in `helpers.py`; master chrome flows through unchanged; layout placeholders stripped at graft.
- For `bespoke` layouts: chrome.yml stores extracted positions; helpers use those.

The template stays pristine. If FedEx re-issues `FDX Template.pptx`, `register_template.py` re-extracts chrome.yml; the original .pptx is read-only.

### 2.3 `layout:` field in brief — fail-loud, with deck-level escape hatch

Briefs declare which layout each slide uses. Three valid forms:

1. **Deck-level default** in front-matter (most common):
   ```yaml
   ---
   client_template: C:\Users\...\FDX Template.pptx
   deck_type: Recommendation / POV
   default_layout: body_canonical_light    # applies to every slide unless overridden
   ---
   ```
2. **Per-slide override** in the slide block:
   ```markdown
   ### Slide 4 — Mid-deck emphasis
   **Layout:** body_canonical_dark
   ```
3. **Cover slide override:**
   ```markdown
   ### Slide 1 — Cover
   **Layout:** cover_light
   ```

**Fail-loud rule:** `build_deck.py` exits at startup with exit code 9 if any slide has no resolvable layout (neither deck default nor per-slide). Error message enumerates the offending slides AND the available layouts from `<stem>.layouts.yml`. **No silent defaults at any level.** See § 5.1 for exact error format.

### 2.4 Bottom-anchor invariant wins over client placeholder anchor

`feedback_title_bottom_anchor.md` says title bottom-y is fixed; 2-line titles grow upward; subtitle never displaces. Client title placeholders are usually top-anchored (PowerPoint default). If we inherit anchor, 2-line titles push subtitle down, breaking the cross-slide visual stability the invariant exists to preserve.

**Decision:** chrome.yml inherits the placeholder's bounding box (x/y/w/h) but Slide Lab keeps `anchor="bottom"` hardcoded in helpers. The placeholder defines WHERE the title region lives; Slide Lab decides HOW text fills that region.

### 2.5 min_body_zone — hard SKELETON_REJECTED (defensive)

When the picked layout's body_zone is smaller than what a pattern needs, the worker emits `# SKELETON_REJECTED: pattern <N> requires <wxh>, layout <name> provides <wxh>` instead of warn-and-scale. Geometric version of Hardline #5.

This won't fire for FedEx-style templates (large body zones). It's a defensive guardrail for future cramped templates. Land with code; ignore if it never fires.

### 2.6 Dark variants via `text_role` field

Each layout in chrome.yml carries:
- `text_role: "dark_on_light" | "light_on_dark"`
- `background: "light" | "dark"` (informational, drives master classification at finalize)

Helpers (`add_title_block`, `add_footer`, body composers) read `text_role` and select text color:
- `dark_on_light` → `TEXT_DARK` / `TEXT_FAINT_ON_LIGHT`
- `light_on_dark` → `WHITE` / `TEXT_FAINT_ON_DARK`

A FedEx-style template with `body_canonical_dark` layout: Slide Lab builds body content at canonical positions; helpers flip text colors via `text_role`; master fills the canvas dark. Mid-deck emphasis slides become structural, not per-pattern hacks.

### P1.1 — `_chrome_schema.py` + manifest entry

**New file:** `slide-builder/scripts/_chrome_schema.py`
**Pattern:** Mirror `_meta_schema.py` shape. Pydantic at `schema_version: int = 1`.

```python
class BoxPx(BaseModel):
    x_px: int
    y_px: int
    w_px: int
    h_px: int
    font_pt: int | None = None
    anchor: Literal["top", "middle", "bottom"] = "top"

class LayoutChrome(BaseModel):
    name: str                                       # layout name from template
    layout_class: Literal["body-canonical", "bespoke"]
    text_role: Literal["dark_on_light", "light_on_dark"]
    background: Literal["light", "dark"]
    has_page_number: bool
    # For bespoke only — None for body-canonical:
    title: BoxPx | None = None
    subtitle: BoxPx | None = None
    footnote: BoxPx | None = None
    source: BoxPx | None = None
    page_number: BoxPx | None = None

class ChromeSpec(BaseModel):
    schema_version: int = 1
    source_template_sha8: str
    layouts: dict[str, LayoutChrome]
```
