Spec gaps (encountered during planning / build)

Gap 1 -- add_eyebrow not implemented. The spec lists it as a helper, but twins/helpers.py has no such function. I worked around it by calling add_text directly with explicit x/y for the section eyebrow on slides 2 and 4 -- but that violates the spec's "do NOT invent positions" rule. Either ship the helper or drop it from the spec.
Gap 2 -- Layout zones are not actually pre-positioned. Spec says "Layout zones pre-positioned in slide-builder/twins/helpers.py" but the helpers are primitives (add_text, add_rect, add_title_block, add_footer). Only title and footer have fixed positions; body zones are ad-hoc per builder. Without per-layout zone constants (e.g., HERO_STAT_NUMBER_BOX, COMPARE_LEFT_BOX, COMPARE_RIGHT_BOX) agents will still drift on layout-internal geometry -- which is most of the variance the curator was rejecting.
Gap 3 -- Canvas mode "dark" has no first-class helper. new_slide() hardcodes a white background and add_title_block uses TEXT_DARK. Building a dark hero meant manually filling the background rect, manually flipping every text color to WHITE, and skipping add_title_block entirely. If dark mode is one of two canvas modes, it needs a new_slide(mode="dark") + an add_title_block color override, otherwise every dark slide is bespoke.
Gap 4 -- "Variant" is undefined as a contract. Spec lists variants (e.g., "50/50, 75/25 asymmetric, stacked-rows" for Compare) but gives no parameters or zone definitions per variant. Two agents reading "50/50" could pick column widths of 580/580 or 540/620 and both feel justified. Either each variant needs zone constants, or the spec should drop variants entirely and let agents pick freely (which is essentially the current state).
Gap 5 -- No guidance on legend/source/footnote placement inside body. Bottom invariant zone is fine, but per-slide source/footnote anchors above the footer (when text wraps long) are unspecified. The current architecture spec inherits this from the existing helpers, so it's only a gap if Layer 5 collision detection is going away -- then no one is checking.
Gap 6 -- Slide 9's "EXACTLY 2 items" rule could be soft-enforced. The spec relies on the agent to honor "no fabrication." A safer pattern: the brief carries item-count as a structured field, and the builder rejects a 3-card layout when the brief field says 2. Right now nothing structural prevents an agent from picking Card-grid 3-card and inventing a third path.

Spec-sufficiency self-assessment

The 9-layout / 2-mode spec was sufficient to pick layouts for all 10 slides in under five minutes without ambiguity -- every slide had an obvious match and the hardline rules (charts only in Chart layout, no two adjacent same layout, exactly-2 = 2) gave clear guardrails. The simplification is a real win at the selection level. However, the spec is critically under-specified at the build level: variants are named but not defined geometrically, dark-mode has no helper plumbing, and the promised add_eyebrow doesn't exist. Building slides 5, 6, 9 required the same per-shape geometry decisions the 19-chassis system at least gave defaults for -- so the complexity didn't disappear, it moved from the curator into the agent. Net: the spec is sufficient for layout choice and adjacency enforcement, but variants and canvas-mode plumbing need one more pass before this architecture beats the curator-acceptance rate.
